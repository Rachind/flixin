# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FlixIn is a pixel-art space racing game written in plain HTML/CSS/JS (no framework, no build step, no bundler, no modules) living in `www/`. It is wrapped into an Android app with Capacitor 8 (`android/` is the generated native project; `MainActivity` is just an empty `BridgeActivity`). App id: `com.tima.flixin`.

`www/` layout:

- `index.html` — DOM markup only (menus, HUD, overlays) + `<script src>` tags.
- `css/style.css` — all styles.
- `js/*.js` — game code, loaded as **classic scripts in a fixed order** (see the bottom of `index.html`): `version` → `core` → `tracks` → `ships` → `progression` → `sprites` → `audio` → `save` → `menu` → `settings` → `editor` → `input` → `game` → `arena` → `render` → `main`.
- `manifest.webmanifest`, `icons/` — PWA manifest and icons.

The game originally was one standalone `flixin.html` and was split into these files; all game behaviour must keep working in a plain browser as well as inside the Android WebView.

UI strings and in-game text are in Russian; keep new user-facing text in Russian.

## Commands

```bash
npm install                      # Capacitor CLI + runtime
npx cap sync android             # copy www/ into android/app/src/main/assets/public (required after every edit to www/)
cd android && ./gradlew assembleDebug   # -> android/app/build/outputs/apk/debug/app-debug.apk (needs JDK 21 + Android SDK)
```

- To try the game quickly, just open `www/index.html` in a browser (or serve `www/` with any static server). `npm run build` is a no-op.
- There are no real tests or linters; `android/app/src/test` and `androidTest` contain only the Capacitor template example tests.
- CI: `.github/workflows/build-apk.yml` runs on push to `main`/`master` (and manually): `npm install` → writes `www/js/version.js` (`APP_BUILD` = `github.run_number`) → `npx cap sync android` → `./gradlew assembleRelease` signed with a fixed key from repo secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`), then publishes a GitHub Release tagged `build-<N>` with `flixin.apk`. `versionCode` = `FLIXIN_BUILD` env (run number). The key must never change, otherwise new APKs can't install over old ones and players lose their `localStorage` progress. Locally (no `FLIXIN_KEYSTORE`) release builds fall back to the debug key.
- In-app updates: the settings screen (Android only, `Capacitor.isNativePlatform()`) checks `api.github.com/repos/Rachind/flixin/releases/latest`, compares the `build-<N>` tag with `APP_BUILD` and opens the APK URL, which Capacitor hands to the system browser for download. Keep the committed `version.js` at `APP_BUILD = 0`.
- `android/app/src/main/assets/public/` is generated by `cap sync` and git-ignored — never edit it directly; edit the files in `www/`.

## Architecture of `www/index.html`

All JS files share one global scope (top-level `const`/`let`/`function` are visible across files), each starts with `"use strict";` and is organised by `/* ---------------- Section ---------------- */` banner comments. Do not convert them to ES modules (`type="module"` breaks when `index.html` is opened via `file://`). Because files run in order, **top-level code that executes at load time may only call functions/read bindings from the same or earlier files**; anything else must be deferred to event handlers or `boot()` in `main.js`, which runs last. When adding a new file, add its `<script>` tag in the right place. Key pieces:

- **Rendering**: the main `#game` canvas is drawn via a low-res offscreen buffer (`pixelCanvas`/`pctx`, downscaled by `PIXEL_K`) and upscaled in `presentPixelBuffer()` for the chunky-pixel look. All sprites (ships, obstacles, logo, joystick) are character-grid arrays (`*_GRID`, `SHAPE_*`) with a color map, drawn via `drawPixelGrid`/`drawShipMatrix`. Separate small canvases are used for menu previews. Core canvas/util code is in `core.js`, the game renderer and HUD in `render.js`.
- **Tracks**: a track `def` is a list of axis-aligned segments `[['R',1800],['D',1200],...]` (`DIRS`). `buildTrack` turns it into waypoints; positions along the track are expressed as arc length `s` (`trackPointAt`, `projectToTrack`), and obstacles/turbulence zones are placed by `s` + lateral `offset`. All of this is in `tracks.js`. Built-in tracks are in `TRACKS`; user-made tracks from the in-game editor are stored in `SAVE.customTracks` and merged via `getAllTracks()` (obstacles/turbulence are auto-generated for them).
- **Game modes**: `raceMode` is `'solo'`, `'ai'` (track racing, alone or vs bots) or `'pvp'` arena duel (square arena, bullets, power-ups, first to `ARENA_WIN_HITS`). These have separate update/render paths (`updatePlayer`/`updateAI` in `game.js` + `render` in `render.js` vs `updateArenaShip`/`updateArenaAI`/`renderArena` in `arena.js`).
- **State machine & loop**: global `STATE` (`menu`, `hangar`, `track`, `countdown`, `racing`, `finished`) drives `frame()` (the single `requestAnimationFrame` loop, `dt` clamped to 0.033). Menu screens are DOM overlays shown/hidden with the `hidden` class; `goToMenu`, `startCountdown`, `endRace`, `endArenaMatch` handle transitions.
- **Ships & progression**: `SKINS` (in `ships.js`) defines ships (base stats, price, shape). Upgrades (`UPGRADE_*`), appearance decals, hull paint, achievements (`ACHIEVEMENTS`), daily challenges (`DAILY_POOL`), ghost replays of best laps and credits all hang off the save object.
- **Audio** (`audio.js`): fully synthesized with WebAudio (`playTone`, `playNoiseBurst`, `playSfx`, procedural music from `MUSIC_SCALES`); no audio files. `resumeAudio()` must be called from a user gesture.
- **Input** (`input.js`): virtual touch joystick (`joyStart/Move/End`) plus keyboard (arrows/WASD, Space to fire in the arena).

## Persistence

All progress is one JSON object `SAVE` in `localStorage` under key `flixin_save_v2` (`loadSave` / `persistSave` in `save.js`). `loadSave` merges the stored data over `defaultSave()` field by field, so **when adding a new save field, add its default to `defaultSave()` and, for nested objects/arrays, add a matching merge line in `loadSave`** — otherwise existing players' saves will lose or break it. Don't rename the storage key unless you intend to reset everyone's progress.

`ONE_TIME_GIFTS` grants credits exactly once per gift `id` (tracked in `SAVE.claimedGifts`); add a new entry with a new unique id to grant a bonus.
