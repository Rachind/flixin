# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FlixIn is a pixel-art space racing game written as a **single self-contained HTML file** (`www/index.html`, ~3900 lines of inline CSS + JS, no framework, no build step, no external scripts). It is wrapped into an Android app with Capacitor 8 (`android/` is the generated native project; `MainActivity` is just an empty `BridgeActivity`). App id: `com.tima.flixin`.

`www/index.html` originally came from a standalone `flixin.html`; the README's update workflow is "copy the new `flixin.html` over `www/index.html` and rebuild". All game behaviour must therefore keep working in a plain browser as well as inside the Android WebView.

UI strings and in-game text are in Russian; keep new user-facing text in Russian.

## Commands

```bash
npm install                      # Capacitor CLI + runtime
npx cap sync android             # copy www/ into android/app/src/main/assets/public (required after every edit to www/)
cd android && ./gradlew assembleDebug   # -> android/app/build/outputs/apk/debug/app-debug.apk (needs JDK 21 + Android SDK)
```

- To try the game quickly, just open `www/index.html` in a browser (or serve `www/` with any static server). `npm run build` is a no-op.
- There are no real tests or linters; `android/app/src/test` and `androidTest` contain only the Capacitor template example tests.
- CI: `.github/workflows/build-apk.yml` runs on push to `main`/`master` (and manually): `npm install` → `npx cap sync android` → `./gradlew assembleDebug`, uploading the `flixin-debug-apk` artifact. Only debug builds exist; there is no release signing.
- `android/app/src/main/assets/public/` is generated by `cap sync` and git-ignored — never edit it directly; edit `www/index.html`.

## Architecture of `www/index.html`

Everything lives in one `<script>` block in global scope, organised by `/* ---------------- Section ---------------- */` banner comments. Key pieces:

- **Rendering**: the main `#game` canvas is drawn via a low-res offscreen buffer (`pixelCanvas`/`pctx`, downscaled by `PIXEL_K`) and upscaled in `presentPixelBuffer()` for the chunky-pixel look. All sprites (ships, obstacles, logo, joystick) are character-grid arrays (`*_GRID`, `SHAPE_*`) with a color map, drawn via `drawPixelGrid`/`drawShipMatrix`. Separate small canvases are used for menu previews.
- **Tracks**: a track `def` is a list of axis-aligned segments `[['R',1800],['D',1200],...]` (`DIRS`). `buildTrack` turns it into waypoints; positions along the track are expressed as arc length `s` (`trackPointAt`, `projectToTrack`), and obstacles/turbulence zones are placed by `s` + lateral `offset`. Built-in tracks are in `TRACKS`; user-made tracks from the in-game editor are stored in `SAVE.customTracks` and merged via `getAllTracks()` (obstacles/turbulence are auto-generated for them).
- **Game modes**: `raceMode` is `'solo'`, `'ai'` (track racing, alone or vs bots) or `'pvp'` arena duel (square arena, bullets, power-ups, first to `ARENA_WIN_HITS`). These have separate update/render paths (`updatePlayer`/`updateAI`/`render` vs `updateArenaShip`/`updateArenaAI`/`renderArena`).
- **State machine & loop**: global `STATE` (`menu`, `hangar`, `track`, `countdown`, `racing`, `finished`) drives `frame()` (the single `requestAnimationFrame` loop, `dt` clamped to 0.033). Menu screens are DOM overlays shown/hidden with the `hidden` class; `goToMenu`, `startCountdown`, `endRace`, `endArenaMatch` handle transitions.
- **Ships & progression**: `SKINS` defines ships (base stats, price, shape). Upgrades (`UPGRADE_*`), appearance decals, hull paint, achievements (`ACHIEVEMENTS`), daily challenges (`DAILY_POOL`), ghost replays of best laps and credits all hang off the save object.
- **Audio**: fully synthesized with WebAudio (`playTone`, `playNoiseBurst`, `playSfx`, procedural music from `MUSIC_SCALES`); no audio files. `resumeAudio()` must be called from a user gesture.
- **Input**: virtual touch joystick (`joyStart/Move/End`) plus keyboard (arrows/WASD, Space to fire in the arena).

## Persistence

All progress is one JSON object `SAVE` in `localStorage` under key `flixin_save_v2` (`loadSave` / `persistSave`). `loadSave` merges the stored data over `defaultSave()` field by field, so **when adding a new save field, add its default to `defaultSave()` and, for nested objects/arrays, add a matching merge line in `loadSave`** — otherwise existing players' saves will lose or break it. Don't rename the storage key unless you intend to reset everyone's progress.

`ONE_TIME_GIFTS` grants credits exactly once per gift `id` (tracked in `SAVE.claimedGifts`); add a new entry with a new unique id to grant a bonus.
